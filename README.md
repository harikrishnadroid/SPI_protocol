# SPI_protocol
# SPI Master-Slave Protocol – Verilog HDL

## Overview

This project implements a **Full-Duplex SPI (Serial Peripheral Interface) Master and Slave using Verilog HDL**.

The design was developed at RTL level to understand how SPI communication works internally, including:

* SPI Master and Slave architecture
* Full-duplex serial communication
* CPOL and CPHA support
* SPI clock generation using a programmable divider
* TX and RX shift registers
* MOSI and MISO data transfer
* SPI chip-select (`SS`) control
* Bit counting
* FSM-based Master control
* Clock-edge detection
* Mode-dependent sampling and shifting
* RTL simulation and waveform debugging

The design uses a system clock (`pclk`) in the Master to generate the SPI clock (`sclk`). The Slave operates directly from the generated SPI clock.

---

# 1. SPI Protocol

SPI is a synchronous serial communication protocol commonly used for communication between a controller/master and peripheral/slave devices.

A basic SPI connection consists of four signals:

| Signal | Direction      | Description                      |
| ------ | -------------- | -------------------------------- |
| `SCLK` | Master → Slave | Serial clock generated by Master |
| `MOSI` | Master → Slave | Master Out Slave In              |
| `MISO` | Slave → Master | Master In Slave Out              |
| `SS`   | Master → Slave | Slave Select / Chip Select       |

The Master controls:

* SPI clock
* Slave selection
* Data transmitted through MOSI

The Slave responds to:

* `SCLK`
* `SS`
* MOSI

and sends data back through MISO.

# 4. SPI Master

The Master module has the following interface:

```verilog
module master(
    input        pclk,
    input        rst,
    input        en,
    output reg   ss,
    input  [7:0] master_tx_data,
    input        cpha,
    input        cpol,
    input        miso,
    input  [7:0] div,
    output reg   mosi,
    output reg   sclk
);
```

### Master Inputs

| Signal           | Description                      |
| ---------------- | -------------------------------- |
| `pclk`           | System clock used by the Master  |
| `rst`            | Reset                            |
| `en`             | Enables SPI transfer             |
| `master_tx_data` | 8-bit data to transmit           |
| `cpha`           | SPI clock phase configuration    |
| `cpol`           | SPI clock polarity configuration |
| `miso`           | Data received from Slave         |
| `div`            | SPI clock divider                |

### Master Outputs

| Signal | Description         |
| ------ | ------------------- |
| `ss`   | Slave Select        |
| `mosi` | Master Out Slave In |
| `sclk` | Generated SPI clock |

# 5. Master FSM

The Master is controlled using a four-state FSM:

```text
              +------+
              | IDLE |
              +--+---+
                 |
                 v
             +-------+
             | LOAD  |
             +---+---+
                 |
                 | en
                 v
          +-------------+
          |  TRANSFER   |
          +------+------+
                 |
                 | count == 8
                 v
             +-------+
             | DONE  |
             +---+---+
                 |
                 v
              +------+
              | IDLE |
              +------+
```

The states are defined as:

```verilog
parameter idle     = 2'b00;
parameter load     = 2'b01;
parameter transfer = 2'b10;
parameter done     = 2'b11;
```

---

# 6. IDLE State

The Master starts in the `IDLE` state.

During this state:

* SPI transfer is inactive.
* `SS` is deasserted.
* SCLK is returned to the configured CPOL level.
* The Master waits before starting the next transaction.

The design uses:

```verilog
ss = 1;
```

as the default state.

Therefore:

```text
SS = 1 → Slave not selected
SS = 0 → Slave selected
```

---

# 7. LOAD State

After the initial `IDLE` state, the FSM enters `LOAD`.

The Master loads the parallel transmit data into the TX shift register:

```verilog
master_tx_shift_reg <= master_tx_data;
```

The first transmit bit is then prepared on MOSI.

The important idea is:

```text
master_tx_data
      |
      v
+-------------------+
| TX Shift Register |
+-------------------+
      |
      v
    MOSI
```

The TX shift register converts the 8-bit parallel data into serial data.

---

# 8. Why a TX Shift Register Is Required

The external interface provides an 8-bit parallel value:

```text
master_tx_data[7:0]
```

However, SPI transmits only one bit at a time.

Therefore, the parallel data needs to be converted into serial data.

For example:

```text
TX DATA

10110010
   |
   v

First bit  → 1
Second bit → 0
Third bit  → 1
...
```

The shift register makes this possible.

The Master uses:

```verilog
reg [7:0] master_tx_shift_reg;
```

During transmission, the register is shifted:

```verilog
master_tx_shift_reg <=
    {master_tx_shift_reg[6:0], 1'b0};
```

This moves the next transmit bit toward the MOSI output.

---

# 9. RX Shift Register

The Master also contains:

```verilog
reg [7:0] master_rx_shift_reg;
```

The purpose of this register is to collect incoming MISO bits.

When a sampling edge occurs:

```verilog
master_rx_shift_reg <=
    {miso, master_rx_shift_reg[7:1]};
```

Therefore:

```text
MISO
 |
 v
+--------------------+
| RX Shift Register  |
+--------------------+
 |
 v
8-bit Received Data
```

This converts the serial MISO stream into an 8-bit parallel value.

---

# 10. Full-Duplex Communication

One of the important characteristics of this design is that transmission and reception occur simultaneously.

During an SPI clock:

```text
              MASTER                 SLAVE

                MOSI  -------------> RX
                                      |
                                      |
                MISO  <------------- TX

                SCLK  -------------> Clock
```

Therefore:

```text
Master TX → Slave RX
Master RX ← Slave TX
```

happens during the same SPI transaction.

This is why separate TX and RX shift registers are used.

---

# 11. SPI Clock Generation

The Master receives a system clock:

```text
pclk
```

but SPI requires a slower serial clock:

```text
sclk
```

Therefore, the design uses a clock counter/divider.

The relevant registers are:

```verilog
reg [2:0] clk_count;
```

and:

```verilog
input [7:0] div;
```

The basic clock-generation mechanism is:

```text
                 PCLK
                  |
                  v
          +---------------+
          | Clock Counter |
          +-------+-------+
                  |
             count == div-1
                  |
                  v
              Toggle SCLK
```

Conceptually:

```verilog
if(clk_count == div-1) begin
    clk_count <= 0;
    sclk <= ~sclk;
end
else begin
    clk_count <= clk_count + 1;
end
```

Thus the SPI clock does not toggle on every `pclk` cycle.

---

# 12. Why a Clock Divider Is Required

If the system clock is much faster than the required SPI clock, directly using `pclk` would make the SPI interface operate at the system-clock frequency.

For example:

```text
PCLK
_|‾|_|‾|_|‾|_|‾|_|‾|_
```

Instead, the divider generates:

```text
SCLK
____|‾‾‾‾|____|‾‾‾‾|____
```

The divider therefore allows the SPI clock frequency to be controlled independently from the system clock.

---

# 13. CPOL – Clock Polarity

`CPOL` determines the idle state of SCLK.

The implementation uses:

```verilog
sclk <= cpol;
```

when the SPI Master is not transferring data.

Therefore:

```text
CPOL = 0
SCLK idle = 0
```

and:

```text
CPOL = 1
SCLK idle = 1
```

Conceptually:

```text
CPOL = 0

SCLK ______/‾‾‾\______/‾‾‾\______


CPOL = 1

SCLK ‾‾‾‾‾\_____/‾‾‾‾‾\_____/‾‾‾
```

This is the first part of defining the SPI mode.

---

# 14. CPHA – Clock Phase

`CPHA` determines which clock edge is associated with sampling versus changing the transmitted data.

SPI supports four combinations:

| SPI Mode | CPOL | CPHA |
| -------- | ---: | ---: |
| Mode 0   |    0 |    0 |
| Mode 1   |    0 |    1 |
| Mode 2   |    1 |    0 |
| Mode 3   |    1 |    1 |

The design therefore cannot simply assume:

```text
posedge = sample
negedge = shift
```

for every mode.

Instead, the Master determines the appropriate edge based on CPOL and CPHA.

---

# 15. Detecting SCLK Edges

The design stores the previous SCLK value:

```verilog
reg sclk_d;
```

The current and previous values are compared to detect edges.

### Positive Edge

```verilog
assign posedge_sclk = sclk & ~sclk_d;
```

This detects:

```text
0 → 1
```

### Negative Edge

```verilog
assign negedge_sclk = ~sclk & sclk_d;
```

This detects:

```text
1 → 0
```

Therefore:

```text
Previous SCLK   Current SCLK

      0    →       1       = Positive edge

      1    →       0       = Negative edge
```

---

# 16. Why `sclk_d` Is Required

The Master generates SCLK using the system clock.

The design needs to know when the generated SCLK actually changed.

For this reason, the previous value is stored:

```verilog
sclk_d <= sclk;
```

Then:

```verilog
sclk & ~sclk_d
```

can detect a rising transition.

Similarly:

```verilog
~sclk & sclk_d
```

detects a falling transition.

This allows the Master logic running on `pclk` to identify SPI clock edges.

---

# 17. Sample Enable

The design creates a mode-dependent sampling signal:

```verilog
assign sample_en =
    ((posedge_sclk) && (cpol == cpha)) ||
    ((cpol != cpha) && (negedge_sclk));
```

The purpose of this logic is to determine:

> On which SCLK edge should the Master capture the MISO data?

When `sample_en` is active:

```verilog
master_rx_shift_reg <=
    {miso, master_rx_shift_reg[7:1]};
```

Therefore, the received bit is shifted into the RX register.

---

# 18. Shift Enable

Similarly, the design generates:

```verilog
assign shift_en =
    ((posedge_sclk) && (cpha != cpol)) ||
    ((negedge_sclk) && (cpol == cpha));
```

This determines when the transmit data should advance to the next bit.

When `shift_en` is active:

```verilog
mosi <= master_tx_shift_reg[6];

master_tx_shift_reg <=
    {master_tx_shift_reg[6:0],1'b0};
```

Therefore, the current transmission advances and the next bit becomes available.

---

# 19. Sample and Shift Concept

The basic SPI operation is:

```text
            SPI CLOCK
              |
              v

        +-------------+
        | Sample Edge |
        +------+------+
               |
               v
             MISO
               |
               v
          RX Register


        +-------------+
        |  Shift Edge |
        +------+------+
               |
               v
          TX Register
               |
               v
             MOSI
```

Which edge performs each operation depends on CPOL and CPHA.

This is one of the main timing concepts implemented in this project.

---

# 20. Transfer Counter

The Master contains:

```verilog
reg [3:0] count;
```

The counter tracks the number of transferred bits.

For an 8-bit SPI transfer:

```text
Bit 0
 ↓
Bit 1
 ↓
Bit 2
 ↓
Bit 3
 ↓
Bit 4
 ↓
Bit 5
 ↓
Bit 6
 ↓
Bit 7
 ↓
Transfer Complete
```

The FSM checks:

```verilog
if(count == 4'b1000)
    next_state = done;
```

Therefore, after eight transfer events, the FSM moves to the `DONE` state.

---

# 21. DONE State

Once the transfer is complete, the FSM enters:

```text
DONE
```

The transfer is terminated and the FSM returns to:

```text
IDLE
```

This allows another transaction to begin.

The overall transaction therefore follows:

```text
IDLE
  |
LOAD
  |
TRANSFER
  |
DONE
  |
IDLE
```

# 22. SPI Slave

The Slave module is implemented as:

```verilog
module slave #(
    parameter cpol = 0,
    parameter cpha = 0
)(
    input  sclk,
    input  rst,
    input  mosi,
    input  ss,
    output miso
);
```

The Slave receives:

* `SCLK`
* `MOSI`
* `SS`
* `RST`

and generates:

```text
MISO
```

---

# 23. Why the Slave Uses the SPI Clock

Unlike the Master, the Slave does not need to generate SCLK.

The Master is responsible for generating the SPI clock.

Therefore:

```text
Master
  |
  | SCLK
  v
Slave
```

The Slave uses the incoming SCLK to determine when to:

* Sample MOSI
* Shift transmit data
* Update MISO

This reflects the normal SPI Master-Slave relationship.

---

# 24. Slave TX Shift Registers

The Slave contains two transmit shift registers:

```verilog
reg [7:0] slave_tx1_shift_reg = 8'b00001111;
reg [7:0] slave_tx2_shift_reg = 8'b11110000;
```

The two registers provide separate transmit paths associated with the two possible edge-handling cases.

The initial data values are:

```text
slave_tx1_shift_reg = 00001111
slave_tx2_shift_reg = 11110000
```

These values are currently hard-coded for simulation/testing.

They can later be changed to inputs or registers if the design is extended.

---

# 25. Why MISO1 and MISO2 Are Used

The Slave contains:

```verilog
reg miso1;
reg miso2;
```

and the final MISO output is selected using:

```verilog
assign miso = (cpol == cpha) ? miso2 : miso1;
```

Therefore, the Slave has two internal MISO paths.

Conceptually:

```text
                 +----------------+
                 | Slave TX Data  |
                 +-------+--------+
                         |
                 +-------+-------+
                 |               |
                 v               v
               MISO1           MISO2
                 |               |
                 +-------+-------+
                         |
                    CPOL / CPHA
                       Select
                         |
                         v
                        MISO
```

---

# 26. Why Separate MISO Paths Are Useful

SPI has different timing relationships depending on CPOL and CPHA.

The Slave therefore needs to handle its transmit data differently depending on the selected mode.

Instead of trying to make a single MISO register operate from both:

```text
posedge SCLK
```

and:

```text
negedge SCLK
```

the design separates the two paths:

```text
MISO1
MISO2
```

and then selects the appropriate one:

```verilog
assign miso =
    (cpol == cpha) ? miso2 : miso1;
```

This makes the mode-dependent behavior explicit in the design.

---

# 27. Slave RX Shift Registers

The Slave also contains two receive registers:

```verilog
reg [7:0] slave_rx1_shift_reg;
reg [7:0] slave_rx2_shift_reg;
```

These registers collect data received from MOSI.

For example:

```verilog
slave_rx1_shift_reg <=
    {slave_rx1_shift_reg[6:0],mosi};
```

This performs serial-to-parallel conversion.

The received sequence:

```text
MOSI:
1 → 0 → 1 → 1 → 0 → 0 → 1 → 0
```

is gradually stored inside the RX shift register.

---

# 28. Slave Positive-Edge Logic

The Slave contains a positive-edge process:

```verilog
always @(posedge sclk or posedge rst)
```

This block handles behavior associated with the rising edge of SCLK.

When:

```text
SS = 0
```

the Slave is selected and the SPI transaction is active.

Depending on CPOL/CPHA, the block either:

* Samples MOSI
* Shifts the Slave TX register
* Updates MISO

---

# 29. Slave Negative-Edge Logic

The Slave also contains:

```verilog
always @(negedge sclk or posedge rst)
```

This block handles behavior associated with the falling edge of SCLK.

Again, CPOL and CPHA determine whether the Slave should:

* Sample MOSI
* Shift TX data
* Update MISO

This separation makes it easier to model the edge-dependent behavior of SPI.

---

# 30. Slave Chip Select

The Slave performs operations only when:

```verilog
!ss
```

is true.

Therefore:

```text
SS = 1
    |
    v
Slave inactive


SS = 0
    |
    v
Slave active
```

The Master controls `SS`, so the Master effectively controls when the Slave participates in the communication.

Both directions operate simultaneously.

# 35. Important RTL Design Decisions

## 35.1 Shift Registers

Separate TX and RX shift registers were used because SPI simultaneously transmits and receives serial data.

## 35.2 Programmable Clock Divider

A divider was used instead of directly connecting the system clock to SCLK so that the SPI frequency can be controlled.

## 35.3 CPOL/CPHA Logic

Sampling and shifting were made dependent on CPOL and CPHA so that the design can operate in the four SPI modes.

## 35.4 Previous SCLK Register

`sclk_d` was introduced to detect transitions of the internally generated SCLK.

## 35.5 Separate MISO Paths

`miso1` and `miso2` were used to handle mode-dependent Slave transmit behavior.

## 35.6 FSM

The Master FSM separates:

```text
Initialization
Data Loading
Data Transfer
Transfer Completion
```

This makes the control logic easier to understand and debug.

# 37. Example Transfer

Assume the Master sends:

```text
master_tx_data = 8'b10110010
```

The Master loads:

```text
TX Shift Register = 10110010
```

The bits are then transmitted serially:

```text
MOSI:

1 → 0 → 1 → 1 → 0 → 0 → 1 → 0
```

At the same time, if the Slave transmits:

```text
Slave TX = 00001111
```

then the Master receives those bits through MISO.

After the required number of sampling events:

```text
Master RX Shift Register
        |
        v
Received 8-bit data
```

Thus one SPI transaction performs both:

```text
Master → Slave
```

and:

```text
Slave → Master
```

simultaneously.

# 38. Reset Behavior

Reset is implemented using asynchronous reset conditions:

```verilog
@(posedge pclk or posedge rst)
```

and:

```verilog
@(posedge sclk or posedge rst)
```

or:

```verilog
@(negedge sclk or posedge rst)
```

During reset, important registers are cleared or initialized.

For example:

```verilog
present_state <= idle;
master_rx_shift_reg <= 0;
count <= 0;
sclk_d <= 0;
```

The Slave similarly clears its receive registers and counters.

# 39. Design Challenges

### Clock Generation

Generating SCLK from a faster system clock required a counter and controlled toggle mechanism.

### CPOL/CPHA

The major timing challenge was determining which SCLK edge should be used for sampling and shifting.

### Full-Duplex Operation

TX and RX have to operate at the same time, requiring independent shift registers.

### MISO Timing

The Slave must update MISO at the correct time so that the Master samples the correct bit.

### Edge Detection

Because SCLK is generated synchronously from PCLK, the Master uses `sclk_d` to detect generated SCLK transitions.

### FSM Control

The FSM coordinates loading, transferring and completing an SPI transaction.

# 43. Known RTL Issue / Future Improvements

The current RTL is a learning/project implementation and can be further improved.

### 1. Slave TX Register Name

In the current Slave code, the following reference appears:

```verilog
miso1 <= slave_tx_shift_reg[0];
```

However, the declared register is:

```verilog
slave_tx1_shift_reg
```

Therefore, this should be corrected to:

```verilog
miso1 <= slave_tx1_shift_reg[0];
```

before synthesis/compilation.

### 2. Clock Divider Width

The Master currently declares:

```verilog
reg [2:0] clk_count;
```

while the divider input is:

```verilog
input [7:0] div;
```

A wider counter, such as:

```verilog
reg [7:0] clk_count;
```

would allow the counter to represent the full divider range.

### 3. Reset/Initialization of Some Registers

Some TX-related registers and outputs can be explicitly reset to make simulation behavior deterministic.

### 4. Slave TX Data

The current Slave TX data is initialized with fixed values:

```verilog
8'b00001111
8'b11110000
```

A future version can make these programmable through inputs or registers.

### 5. Transfer Completion

The design can be extended with a `busy` or `transfer_done` output so that an external controller can clearly determine when the SPI transaction has completed.

### 6. Parameterized Data Width

The current design uses 8-bit data. It can be generalized using a parameter:

```verilog
parameter DATA_WIDTH = 8;
```

to support different SPI transfer widths.

# 45. Conclusion

This project implements a **Full-Duplex SPI Master-Slave communication system using Verilog HDL**.

The design was built from fundamental RTL components rather than relying on a pre-existing SPI controller.

The key implementation concepts are:

```text
Parallel TX Data
       |
       v
TX Shift Register
       |
       v
     MOSI
       |
       v
   SPI Slave
       |
      MISO
       |
       v
RX Shift Register
       |
       v
Parallel RX Data
```

The Master controls the communication using an FSM and generates SCLK from the system clock using a programmable divider.

CPOL and CPHA are used to determine the SPI clock behavior and the appropriate sampling/shifting edges.

The Slave uses separate transmit/receive paths and `MISO1`/`MISO2` handling to implement mode-dependent serial transmission.

Overall, this project provided practical experience in **Verilog RTL design, SPI protocol implementation, FSM design, clock generation, shift-register design, timing analysis, and waveform-based debugging**.
